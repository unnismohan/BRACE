Test management for Robot Framework

Robot Framework runs your tests. BRACE gives your team everything around them — projects, suites, parallel execution, scheduling, reports and alerts. Separate project runners keep test execution apart from the controller. Self-host on Docker or Kubernetes, with no external database.

What it does

The things every team ends up building by hand once they run Robot Framework at any scale.

Parallel execution

Cases execute concurrently within configurable run and browser limits. Fair queues share available run slots across projects. Size worker resources and concurrency for your test workload.

Failure summaries inline

The failing keyword, Robot's own message and the screenshot, pulled from output.xml — no opening log.html to find the red line.

Re-run only what failed

Re-run the failed subset as a linked diagnostic run. Optional automatic retries preserve each attempt and flag a later pass as flaky; retries repeat the test file and its side effects.

Scheduling

Cron per suite, with a live preview of the next fire times in your timezone — validated before you can save it.

Coverage reporting

How much of your suite has ever actually run, which scripts were never onboarded, and which cases have gone stale.

Email notifications

Configure per-project outcome notifications, including alerts when the result changes, to keep recurring failures from overwhelming your inbox.

Projects and roles

Viewer, tester and project admin, enforced per request. Git sync per project, tokens encrypted at rest.

Built for locked-down networks

The UI needs no CDN or npm build step. Git sync, email, optional AI and external test targets need approved network access. Offline deployments require preloaded images and dependencies.

Environment profiles

Select project-specific variables and encrypted test secrets. Each queued run preserves its selected profile snapshot.

Test quarantine

Exclude unstable cases from normal and scheduled runs with a recorded reason. Include them explicitly for diagnosis and restore them when fixed.

Project overview

See execution coverage, queues, active work, recent failures and upcoming schedules. Open failure details directly from the dashboard.

Search and pagination

Search across cases and runs, with paginated lists and persistent account/project filters. Case selections survive page changes.

Quick start

Trusted local testing with Git, Docker and Docker Compose.

# local mode: test scripts execute inside the controller
git clone https://github.com/unnismohan/BRACE.git && cd BRACE
docker compose -f docker-compose.local.yml up -d --build

Open http://localhost:8080 and sign in as admin / admin on a fresh local database. Change the initial password before continuing, then create a project and upload or Git-sync your Robot scripts. Local mode gives scripts access to the controller's files and credentials.

For isolated deployment, use the two-container Compose example with generated credentials, or follow the Kubernetes deployment guide. Kubernetes uses one controller replica and one dedicated runner replica per project. Runner replica autoscaling is not supported yet. See the execution guide for configuration and isolation boundaries.
