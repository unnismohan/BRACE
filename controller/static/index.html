Daily Activity

            runs per day, stacked by tester
          

          

        

        

          What these numbers mean. They come from execution records only —
          runs triggered, tests executed, and machine execution time.
          Execution time is not time worked: it is how long the runner was busy,
          including waits while nobody was at a keyboard. Script authoring, debugging and
          reviewing are not captured at all. Use this to see throughput and coverage
          trends, not to measure a person's effort.

🔗 Test Cases from Git

            

              In git mode the repository decides which test cases exist: every test in a
              Testcases folder becomes a BRACE test case, and its [Tags]
              and [Documentation] come from the file. Run history is kept, and test
              cases you created by hand are never touched.

🧹 Housekeeping

        

          The database grows by runs × test cases, and every case leaves a log and a report
          on disk. Retention deletes runs past a cut-off; the nightly job also reclaims
          orphaned result folders and compacts the database.
        

        

        

          
          
        

        

      


      
      

        

          
📜 Audit Log 

          
        

        

          Every change made through BRACE — runs started, test cases and suites edited,
          schedules and settings changed, members and roles altered. Reads are not recorded,
          and passwords, tokens and API keys are recorded as changed, never as their value.
